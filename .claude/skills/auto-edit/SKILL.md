# 자동 편집 파이프라인 (auto-edit)

사용자(카스)가 **소스 폴더 경로**를 알려주면, 같은 폴더의 촬영본을 `TEMPLATE.md` 지침대로
편집해 완성된 MP4를 뽑는다. 카스는 비개발자다 — 진행 상황은 쉬운 말로 보고하고,
기술 용어를 나열하지 않는다.

## 입력

소스 폴더에는 보통 두 종류의 영상이 있다:

| 소스 | 특징 (자동 판별 기준) |
|---|---|
| **화면 녹화** | 해상도가 모니터 비율(16:9 또는 16:10), 파일명에 screen/화면/녹화 등, 오디오가 없거나 시스템음뿐 |
| **얼굴 촬영** | 카메라 비율(16:9, 9:16, 4:3), 파일명에 face/cam/얼굴 등, 사람 음성 포함 |

판별은 `ffprobe`(해상도·오디오 스트림)와 파일명으로 하되, 애매하면 각 영상의 첫 프레임을
추출해 `Read`로 직접 보고 판단한다. 그래도 애매하면 사용자에게 묻는다.

## 작업 순서

**0. 준비 확인.** `ffmpeg`/`ffprobe`가 있는지, HyperFrames 스킬이 설치돼 있는지 확인:
```bash
which ffmpeg ffprobe || (apt-get update -qq && apt-get install -y -qq ffmpeg)
ls ~/.claude/skills/hyperframes 2>/dev/null || npx hyperframes skills update
```

**1. 소스 파악.** 폴더 안 영상들을 `ffprobe`로 훑고 화면 녹화 / 얼굴 촬영을 판별한다.
길이가 서로 다르면 어떻게 맞출지(짧은 쪽 기준? 특정 구간?) 사용자에게 확인한다.

**2. 대본 추출.** 얼굴 촬영(음성이 있는 쪽)에서 타임스탬프 자막을 뽑는다.
`.claude/skills/watch/scripts/` 의 transcribe 스크립트를 재사용한다 (Whisper 키가
`~/.config/watch/.env`에 필요). 키가 없으면 사용자에게 자막 텍스트를 직접 받거나,
자막 없이 진행할지 묻는다.

**3. 편집 계획.** `TEMPLATE.md`를 읽고 대본을 구간별로 나눠 편집 계획을 세운다:
- 어떤 구간에 화면 녹화를 크게, 어떤 구간에 얼굴을 크게 쓸지
- 자막의 강조 단어(색상 하이라이트) 선정
- 줌인(punch-in)·화면 효과를 넣을 순간 선정
계획을 사용자에게 짧게 보여주고 확인받은 뒤 진행한다.

**4. HyperFrames 합성.** `/hyperframes` 라우터 스킬을 읽고 그 워크플로우를 따른다.
TEMPLATE.md의 수치(자막 폰트·크기·색, 얼굴 화면 위치·크기, 전환 시간 등)를 그대로 쓴다.
소스 영상은 `media-use` 스킬 방식으로 로컬 파일을 참조한다.

**5. 검증 → 렌더링.** `hyperframes check`로 lint를 통과시키고, 몇 개 프레임을
스냅샷으로 뽑아 `Read`로 직접 확인(자막 겹침, 얼굴 화면 가림 등)한 뒤
`hyperframes render`로 MP4를 뽑는다.

**6. 납품.** 완성 MP4 경로를 알려주고, 가능하면 SendUserFile로 보낸다.
수정 요청이 오면 3번부터 다시 돈다.

## 스타일의 유일한 원천

모든 스타일 결정(폰트, 색, 위치, 효과 타이밍)은 이 폴더의 **`TEMPLATE.md`** 를 따른다.
임의로 다른 스타일을 발명하지 않는다. TEMPLATE.md에 없는 결정이 필요하면
TEMPLATE.md의 "기조"에 맞춰 정하고, 정한 내용을 사용자에게 알린 뒤 TEMPLATE.md에
추가 제안한다.

> ⚠️ TEMPLATE.md 상단의 상태 표시를 확인할 것. `상태: 초안`이면 아직 참고 영상
> (https://youtu.be/Y0b-fqge9mI) 분석 전의 기본값이라는 뜻이다. 이 경우 편집은
> 진행하되, 결과물이 참고 영상과 다를 수 있음을 사용자에게 미리 알린다.
